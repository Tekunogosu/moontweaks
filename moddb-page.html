MoonTweaks

Tweak your Vintage Story server in Lua.

Change recipes, retune items and blocks, add commands, react to what players do — by dropping a text file in a folder and restarting. No C# project, no compiler, no toolchain.

Built for server owners who want to customize their servers with ease.

Server-side only  ·  Singleplayer compatible  ·  MIT licensed

Why use it?

Bridge two mods

Add the recipe that lets one mod's output feed another mod's machine. A script can check which mods are actually loaded first, so one file serves several servers.

Create quality-of-life recipes

Firewood back into sticks, a cheaper ladder, the recipe your pack forgot. Add, remove or replace any grid, knapping, clay, smithing, barrel, alloy or cooking recipe.

Rebalance on your terms

Tool durability, stack sizes, mining speed, block drops, food nutrition, burn times. Retune one item by name, or every axe at once by tag.

Set house rules

Set spawns, heal players on respawn, hand out a starter kit on first join, announce the temporal storm, keep a score across the whole world.

Create your own commands

Declare a command with subcommands, typed arguments and a required privilege. The game completes it as it is typed, and players need nothing installed to run it.

Design whole features

The examples include a working levelling system — experience for what you kill, a reward every fifth level. Copy it and make it yours.

Getting started

1 Drop the zip in the Mods folder of whatever runs the world, server or singleplayer.
2 Start it once. MoonTweaks creates its own folder in your ModConfig folder with all necessary files to create your own scripts.
3 Copy an example into scripts/ and change it, or write your own. Scripts run in name order, and folders group them.
4 Restart, then run /moontweaks list to see exactly what your scripts changed.

MoonTweaks directory structure

ModConfig/moontweaks/
  scripts/     your scripts go here
  examples/    example scripts sorted by topic
  library/     editor files used for autocomplete
  config.json  MoonTweaks settings

Editor autocomplete from the start

The mod writes a type library from its own bindings, plus a list of every item, block, tag and trait code your install actually holds — including modded ones.

Any editor running lua-language-server then completes every function, checks the arguments, and suggests codes inside the quotes as you type. In VS Code it is one prompt; the config file is already written.

 

Point your editor to ModConfig/moontweaks/ and your editor will pick up the rest.

 

Note: Only files for nvim and vscode are present. If you have a config you would like to add for a different editor, open a PR or create a new issue on github to have it included

Try it before you restart

/moontweaks check runs every script again on the live server and tells you what it would change, or which line broke — then throws the result away. Nothing is applied and nobody is disturbed, so you can get a script right while people are playing.

 

Unfortunately, due to the way resources are applied, there is no way to hot-reload the scripts, you must restart for changes to take effect.

A mistake never half-applies

Changes are collected as your scripts run and committed only once every one of them has succeeded. A script that fails on line 40 applies nothing at all, and the log names the file, the line, the call and the argument:

99-broken.lua:1: recipes.grid.add argument
'recipe' has no field 'ingredents';
did you mean 'ingredients'?
no changes were applied

What a script looks like

These examples ship with the mod and are located in your ModConfig/moontweaks/examples/ folder

Firewood into sticks

Any axe beside firewood gives four sticks and costs one durability. Matched on the axe tag rather than a specific code, so a modded axe qualifies too.

scripts/10-sticks.lua
local grid = moontweaks.recipes.grid

grid.add {
  name = "moontweaks:sticks-from-firewood",
  pattern = { "AF" },
  ingredients = {
    A = { tags = { "tool-axe" },
          isTool = true,
          toolDurabilityCost = 1 },
    F = "game:firewood",
  },
  output = { code = "game:stick", quantity = 4 },
}

Sleep here, respawn here

Using a bed sets that location as your spawn point. 

 

scripts/20-beds.lua
local events  = moontweaks.events
local players = moontweaks.players

events.didUseBlock(function(e)
  if e.block and e.block:find("bed") then
    players.setSpawn(e.player, e.x, e.y, e.z)
    players.say(e.player,
      "Your spawn is now this bed.")
  end
end)

What it can do

The full reference can be found here:  https://tekunogosu.github.io/moontweaks

Recipes
Add, remove and count every kind: grid, knapping, clay forming, smithing, barrel, alloy and cooking. Kinds other mods invent can be counted and thinned out too.		 Items & blocks
20 item properties and 16 more that only blocks have — durability, stack size, tool tier, mining speed, drops, light, walk speed, nutrition, burn time and the rest. Declare tags of your own and put them on whatever should carry them.		 Picking targets
Name a code, use a * wildcard, or select by tag —"every axe", "every tool that is not a weapon" — in the game's own condition grammar.
Players
Position, health, hunger, tiredness, game mode, spawn point — read and written — what they are looking at, chat and chat groups, privileges, per-player stats such as walk speed, data saved with them, and disconnecting them.		 World
Read, place, break and swap blocks; queue a large batch and commit it at once; undo it again; search a region; read light, climate and wind; move the world spawn; play sounds and particles. Read the land claims anywhere, and add or remove one.		 Entities
Find creatures and dropped stacks by code, tag or radius, spawn and despawn them, hurt, heal, rename, set alight, and remember things against one.
Inventory
Read and write any set of slots — a player's bags, a chest, a creature's inventory, the held slot. See how worn each thing is. Moves report how much actually fitted.		 Events
30 of them: join, leave, death, respawn, game mode change, blocks used, broken and placed, entity spawn and death, chunk load, save game events and more. One of them is asked rather than told: a script can refuse what a player is about to build, break or open.		 Commands
Your own /command, with subcommands, six argument types the game parses and completes for you, and a privilege to sit behind.
Calendar
Read the date, season, hemisphere and moon phase. Move time forward, change how fast it passes, or hold the world at one point in the year.		 Server
Read name, uptime, player count, seed, sea level and map size. Turn PvP, fire spread, falling blocks and creature spawning on or off, retune how fast the world grows, and declare a privilege for your own commands.		 Other mods
Check whether a mod is loaded and at what version. Weather, temporal stability and block reinforcement are reachable from the base game using this system.

What it cannot do

Worth reading before you plan around it.

× Nothing on the client. No custom GUIs, HUDs, rendering, item names or descriptions. MoonTweaks is server-side only, and those things live on the player's machine. If there is a call for it, I will create a client version as well. 
× No new items, blocks or creatures. A new asset needs its model, textures and name delivered to every player, which is a C# mod. MoonTweaks reshapes what your server already has.
×

No live reload. The game builds its asset packet once at startup, so a changed recipe only reaches players after a restart. Use

/moontweaks check to check your scripts during runtime.
× Smaller gaps. Worldgen, explosions, ray casting and decor are out of reach. A script can declare a privilege and read who holds one, but never grant it, and it can select creatures by tag without being able to give one a new tag.
Which parts of Lua are available

Scripts use Lua 5.2, every number is a double and goto is not a keyword.

Available: the basic library, string, table, math and bit32.

Absent: io, os, coroutine, debug, package and utf8, along with require, load, loadstring, dofile and loadfile. A script cannot reach a file, cannot pull in another script, and has no clock of its own — the mod provides one.

Every script shares one environment, so a global set by one is visible to the next. local keeps a name to the file that declared it.

Performance

Lua is slower than C#, and here are the numbers.

~7,000

calls fit in a millisecond, and the server ticks every 33 ms

Every call crosses from Lua into C#, and that crossing is the unit of cost. Scripts run on the server's main thread, so what matters is not how much a script does but how long it holds the tick while doing it.

The figures below were taken on one machine, on an empty server, and are rough. A performance suite ships with the examples: copy it into scripts/ and it measures your own server, and adds a /perf command to take the readings again.
A line of Lua — arithmetic, a table write 20–30 ns
A call to a Lua function ~100 ns
A call into MoonTweaks 110–210 ns
A call handing back a table, such as server info 1.3 µs
Reading one block 0.4–0.5 µs
Queueing one block for a batch write 0.4 µs
Writing one block 2–2.5 µs
Scanning a region, per block 20–30 ns
The budget is a slice of a tick. The server ticks about every 33 ms, and every handler, every other mod and the world itself share that tick. So the figure to aim at is not the 500 ms at which the server starts complaining about a slow tick — that is the disaster mark, not a budget. A handler that finishes in a millisecond or two is invisible to players. One that needs longer belongs in server.every, doing a slice per tick.
Fewer calls, not faster ones
Scanning a region in one call costs about 25 ns a block; walking it block by block costs around 450. Where a function takes a whole region or list, hand it the lot.		 Queue bulk edits
An immediate write re-sends the chunk to every player in range, once per block. A committed batch does it once per chunk.		 Split big jobs by time
Spread work across ticks and give each slice a deadline in milliseconds rather than a guessed block count. The example builder fills 25 ms and hands the rest back.

Commands

Administrators hold these by default; the required privilege is one line in config.json.

/moontweaks list
What your scripts changed when the server started.		 /moontweaks check
Run every script again and report what it would change, applying nothing.		 /moontweaks export
Refresh the editor's code list after adding a mod. (This happens automatically upon a restart)
